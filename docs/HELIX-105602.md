# CVE-2026-105602 — Helix Ultimate Mega Menu badge XSS analysis

## Scope and fixtures

- Vulnerable source tree: `D:\ProofCMS-Labs\archives\joomla\helix-ultimate-2.2.10`
- Fixed source tree: `D:\ProofCMS-Labs\archives\joomla\helix-ultimate-2.2.11`
- Existing shared lab: `labs/cve-2026-57829` (Joomla 5.2.5 + Helix Ultimate 2.2.4;
  the 2.2.10 probe was run against that stack)
- Module: `proofcms/modules/joomla/cve_2026_105602.py`

## What actually changed in 2.2.11

Normalized-content diffs (ignoring CRLF) show:

- `src/Platform/Helper.php`
  - `sanitizeMegaMenuBadge()` changes from
    `htmlspecialchars(trim(strip_tags($value)), ENT_QUOTES, 'UTF-8')` to
    `trim(strip_tags(InputFilter::getInstance()->clean($value, 'STRING')))`.
  - New `createPreviewToken()` / `isAuthorizedPreview()` methods and a
    `helixPreview` token check before draft template settings are loaded.
  - `sanitizeEmbed()` filter flags change, and several query/path helpers are
    hardened (`ParameterType`, `DIRECTORY_SEPARATOR`).
- `core/lib/helixmenuhelper.php`, `src/Core/Lib/helixmenuhelper.php`,
  `fields/helixmegamenu.php`, `src/fields/helixmegamenu.php`,
  `layout/megaMenu/megaFields.php`, `layout/megaMenu/sidebar.php`,
  `layout/megaMenu/container.php` and `layout/fields/text.php` are
  byte-identical apart from line endings.
- `layout/megaMenu/container.php` already escapes the settings JSON with
  `htmlspecialchars(json_encode($settings), ENT_QUOTES | ENT_SUBSTITUTE)` in
  both versions.
- `layout/fields/text.php` already escapes the badge input value with
  `htmlspecialchars(..., ENT_QUOTES, 'UTF-8')` in both versions.

## Path analysis

### AJAX `saveMegaMenuSettings` (the current probe)

- `src/Platform/Request.php` routes `saveMegaMenuSettings` through
  `Helper::guardAjaxRequest($method)`, which calls `Session::checkToken()`.
- `Response::saveMegaMenuSettings()` also requires a logged-in user with
  `core.admin` or `core.edit` on the menu type.
- It then calls `Helper::sanitizeMegaMenuSettings()`, which sanitizes
  `badge` with `sanitizeMegaMenuBadge()` before storing the JSON in the menu
  item params.
- In 2.2.10 that sanitizer strips tags and HTML-encodes quotes. The frontend
  `HelixultimateMenu::item()` then applies `htmlspecialchars()` again, so a
  payload is double-encoded rather than rendered as markup.
- The unauthenticated module probe therefore gets an authorization/token
  rejection and cannot reach the badge sink. This explains the existing
  `NOT_CONFIRMED` result.

### Standard Joomla menu-item form (plausible remaining sink)

- The menu item edit form stores the Mega Menu JSON in
  `jform[params][helixultimatemenulayout]`.
- The deprecated field `fields/helixmegamenu.php` (`getInput()` and
  `textFieldHTML()`) writes `$this->value` / `$value` into a quoted HTML
  attribute without escaping. The modern `layout/fields/text.php` path does
  escape, but the deprecated field is still shipped for the J3 path.
- A user who can edit a menu item could store a badge value containing a
  quote and an event handler through the standard form, bypassing the AJAX
  `sanitizeMegaMenuSettings()` call. Reopening the menu item edit page could
  then break out of the `value` attribute.
- This path requires an authenticated menu editor and a form POST; the
  current unauthenticated probe does not exercise it.

### Draft preview

- 2.2.11 adds a random preview token and `isAuthorizedPreview()` before draft
  settings are loaded. 2.2.10 only checks `core.edit`/`core.admin` plus
  `helixMode=edit`.
- This is a separate authorization hardening in the same release, not proof
  that the badge value is rendered raw on the frontend.

## Disposition

`NOT_CONFIRMED` for the current unauthenticated AJAX probe. The public
`saveMegaMenuSettings` path is authenticated, CSRF-guarded and sanitizes the
badge in 2.2.10; the frontend output is escaped again.

The remaining plausible CVE path is the authenticated standard menu-item form
and the deprecated admin field. It needs a dedicated lab with:

1. Joomla 5.2.5 + Helix Ultimate 2.2.10 (vulnerable) and 2.2.11 (control).
2. An administrator/menu-editor session and a published menu item.
3. A standard `com_menus` item save with an inert badge marker containing a
   quote (no script), then a reload of the edit page.
4. A check for the raw marker in the badge input / hidden JSON and, only if
   safe, an inert event-handler attribute to prove execution.

If the standard form filters the value in 2.2.10 as well, the CVE is not
reproducible from these source trees and should remain `NOT_CONFIRMED` with
this document as the analysis record.
